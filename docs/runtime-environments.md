# Proton A/B 运行环境

Oddity 可以为同一份游戏安装创建多个 prefix, 分别使用不同的本地 Proton 版本. 所有 prefix 均由 Oddity 管理, 启动游戏前必须先创建并选择运行环境.

## 创建与切换

1. 退出游戏及手动启动的 Wine 程序, 等待资源任务结束.
2. 打开 **设置 → 运行环境**, 点击 **创建运行环境**, 在弹窗中选择国服或国际服, 输入名称并选择已安装的 Proton 文件夹. 未安装的区服会置灰. 文件夹应包含 `proton` 和 `toolmanifest.vdf`.
3. 点击 **创建环境**. 首个环境自动设为当前和稳定环境, 首次启动时由 Proton 初始化 Windows 环境.
4. 要测试其他版本, 选中源环境并点击 **创建环境或副本**. 绑定区服可独立选择; 创建来源可选择全新环境或某个已有环境. 复制时默认使用源环境的 Proton, 可改为另一版本.
5. 在列表中选择新环境并点击 **切换到此环境**. 测试结束后可以切回稳定环境, 或将验证可用的环境 **保留为稳定环境**.

创建副本不要求源环境先切换为当前环境, 也不改变当前选择. 所有环境自动保存, 重启 Oddity 后仍可选择. 保留为稳定环境只更新标记, 不移动 prefix, 也不自动切换当前环境.

环境绑定所选区服的游戏目录. 切换环境时会同步切换游戏地区. 更换游戏安装目录后, 应为该安装创建环境.

## 隔离范围

每个副本有独立的 prefix 文件、注册表及日志. 游戏资源继续使用同一份安装, 不需要重新下载. 支持写时复制的文件系统可以减少副本的实际占用; 创建前会按普通复制所需大小检查可用空间.

复制会重定向 prefix 内部的链接. 游戏和 Proton 文件链接保持共享; 切换过版本的 prefix 可能仍引用此前的 Proton, 克隆时会校验该兼容层的安装目录, 被引用的兼容层需要保留. Windows 用户目录中映射到宿主的目录改为空目录, 其他宿主盘符和设备映射不继承. 无法判断用途的外部链接会使创建失败, 未完成副本不会进入列表. 新路径中的登录状态是否有效取决于官方组件, 首次启动可能需要重新登录.

这项功能不是文件系统或安全沙箱. 下列状态不会随切换恢复:

- 共享游戏目录中的更新、官方启动器配置、服务器缓存及其他可写文件.
- 通过宿主盘符访问的文件及云端账号状态.
- 系统驱动、umu 及其共享运行时.

因此, 游戏更新后切回稳定环境仍会使用更新后的游戏文件. Proton A/B 环境不提供游戏版本回退或性能基准测试.

## 固定 Proton 版本

运行环境固定所选 Proton 的实际路径及版本标识. 指定版本不存在或版本标识发生变化时, Oddity 会报错, 不会自动选择其他版本.

版本标识检查覆盖 `proton`, `toolmanifest.vdf` 和存在时的 `version` 文件, 不等于对整个 Proton 目录进行完整性校验. 需要使用另一版本时, 应创建新环境.

## 删除与日志

切离待删除环境后, 可以点击红色的 **删除环境**. 弹窗显示环境名称, 确认后删除其受管 prefix. 当前环境和标记为稳定的环境不可删除. 若要删除稳定副本, 应先选择其他稳定环境.

受管 prefix 位于 `~/.local/share/oddity/environments/<环境 ID>/prefix`. 日志位于 `~/.local/share/oddity/logs/environments/<环境 ID>/`, 可以通过 **设置 → 诊断与维护** 的 **导出日志** 一并导出. 日志会保留用于排查已删除环境的问题. 设置了 `XDG_DATA_HOME` 时, 路径随之调整.

游戏运行期间和环境操作期间, Oddity 会拒绝冲突的环境变更、资源写入和运行路径修改. 创建失败时会清理临时副本; 删除登记提交失败时会恢复目录, 提交前中断的删除会在下次启动时恢复.
